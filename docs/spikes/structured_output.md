# 스파이크 — 구조화 출력

## 목적 및 SPEC 근거

사진 분석 결과를 프로그램이 읽고 옷장과 대조할 수 있도록, OpenAI Structured Outputs strict 모드의 JSON 형식 준수를 확인한다.

- [SPEC AC1](../SPEC.md): 태깅과 옷장 칩은 같은 enum 목록만 사용한다. 목록 밖 값이 하나라도 있으면 실패하며 스키마로 판정한다.
- SPEC 3·5절: 사진 태깅을 `POST /analyze`의 입력 단계로 삼아 갭 분석, 코디 조합, 쇼핑 링크로 연결한다. 스키마는 `src/fulljoin/schemas/style_image.schema.json`이다.

## 핵심 기술적 리스크

API가 스키마를 거부하거나, JSON 파싱·필수 키·enum 검증에 실패하면 사진 속 Item을 안정적으로 처리할 수 없다. 이는 옷장 대조(AC9), 코디 조합(AC11), 구매 아이템 검색 링크(SPEC 4절)의 선행 단계에 영향을 준다. 스타일 태깅을 쓰는 아카이브·피드 필터(AC5·AC15), 저장된 분석 결과를 재사용하는 챗봇(AC14)도 영향을 받는다. 이 스파이크는 해당 후속 기능의 구현이나 성능을 검증하지 않는다.

## 최종 결론 및 한계

**스파이크 합격: 두 부분 실행을 합쳐 3/3장이 형식 성공 기준을 충족했다.** 이 모델·프롬프트·스키마 조합이 이번 세 사진에서 동작함을 확인했다. 착장 인식 정확도, 보이지 않는 옷의 생성 여부, 전체 입력에서의 안정성은 아직 검증하지 않았다. 세 건 성공으로 E7의 형식 준수율 99%를 입증할 수 없다.

실험 후 사용자가 원본 이미지와 모델 출력 태그를 수동으로 비교한 결과, 일부 색상·재질·형태 분류에서 불일치 가능성이 관찰되었다. 이는 정량적 정확도 평가가 아니며, 자동화된 JSON Schema 검증에 따른 이번 스파이크의 합격 판정과는 별개로 구체적인 사례는 추후 Evals에서 검토할 예정이다.

측정한 시간은 업로드 시 태깅 API 호출 시간이다. AC3은 이미 태깅된 피드 사진을 사용자가 ♡한 뒤 갭 분석 결과를 보여 주는 시간으로, 이번 평균 5.73초로 AC3 통과·실패를 판정하지 않는다.

기존 재도전 기준은 유지한다: 세 장 중 하나라도 실패하면 칩 목록을 줄여 1번 재실험하고, 계속 실패하면 다른 모델로 같은 세 장을 비교한다. 스키마·프롬프트 변경과 추가 호출은 별도 승인 후 진행한다. 이번에는 재도전하지 않았다.

## 추후 Evals에서 검증할 항목

[Evals 설계](../../evals/README.md)의 기준을 따른다.

- E1: 사람 정답과 부위·종류·색 비교, 정확도 80% 이상(핏은 기록만).
- E2·E3: 옷장 대조 일치율 80% 이상, 가진 옷을 구매로 판정한 비율 10% 이하(AC9).
- E4·E5·E6: 근거 없는 브랜드·제품명, 옷장에 없는 코디 id, 옷 없는 사진의 Item 생성 각각 0건(AC2·AC11·AC10).
- E7: 더 넓은 평가 세트에서 형식 준수율 99% 이상(AC1).
- E8·E9: 응답 시간과 다시 열 때 분석 호출 0회 검증. E8의 현재 측정 정의는 사진 저장부터 결과까지로, AC3의 ♡ 이후 갭 분석 시간과 구분해 기록한다(AC3·AC4).
- E10·E11: 챗봇의 없는 옷 생성 및 사진 재분석 각각 0회(AC14).
