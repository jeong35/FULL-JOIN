# 스파이크 — 인스타·핀터레스트에서 본 사진을 우리 앱으로 가져올 수 있는가

> 핵심 기능이 얼마나 잘 되는지(태깅 정확도, 옷장 대조 일치율)는 스파이크가 아니라 **evals**에서 잰다 → `evals/README.md`

## 1. 왜 이것인가

- 우리 앱의 입력은 **사용자가 본 스타일 사진**뿐이다. 사진이 들어오지 않으면 태깅도, 옷장 대조도, 추천도 없다.
- 인터뷰에서 사진은 인스타 저장·캡처·DM·핀터레스트에 흩어져 있었다(로그 1, 3~10).
- 인스타 저장 목록은 공식 API로 가져올 수 없다. 남는 길은 **공유하기**와 **캡처 업로드**뿐이다.
- 인스타·핀터레스트는 공유할 때 이미지 대신 **링크만** 보내는 경우가 있다. 링크만 오면 이미지를 얻으려고 페이지를 긁어야 하는데, 이는 약관·저작권 문제로 하지 않는다.

## 2. 성공 조건 (실험 전에 정함)

| 무엇을 본다 | 합격선 |
|---|---|
| 게시물 10개(인스타 5, 핀터레스트 5)를 "공유하기"로 우리 앱에 보냈을 때 **이미지 파일**을 받은 개수 | 10개 중 8개 이상 |
| (참고) 캡처 사진을 갤러리에서 골라 올리기까지 누르는 횟수 | 3번 이내 |

## 3. 방법 (하루)

1. Expo로 공유 받기만 되는 최소 앱을 만든다(공유 기능은 Expo Go가 아니라 개발 빌드가 필요할 수 있다).
2. iPhone·Android 중 팀원이 가진 기기에서 게시물 10개를 공유하기로 보낸다.
3. 게시물마다 "이미지 받음 / 링크만 받음 / 실패"를 기록한다.

## 4. 결과와 판단

_실험 후 작성._

| | 결과 | 합격선 | 판정 |
|---|---|---|---|
| 이미지 수신 | /10 | 8 | |
| 캡처 업로드 누름 횟수 | 번 | 3번 | |

- 미리 정한 반영 방향
  - 통과 → 공유하기를 기본 흐름으로, 캡처 업로드는 보조
  - 미달(링크만 옴) → 캡처 업로드(갤러리에서 여러 장 한 번에 선택)를 기본 흐름으로 바꾸고, 첫 화면에서 "캡처해서 올리세요"를 안내한다
