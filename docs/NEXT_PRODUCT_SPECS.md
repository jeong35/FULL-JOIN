# 후속 개발 명세와 의존성

이 문서는 다음 작업의 경계만 정의한다. 현재 브랜치에서 아래 기능을 운영 코드로 구현하지 않는다.

## 코사인 B안 실험

- A안의 AC9 버킷을 운영 기준으로 유지한다.
- B안은 전체 후보 확장이나 임계값 판정 변경을 실제 사용자 응답에 적용하지 않고 shadow 결과로만 계산한다.
- 팀 라벨 데이터, 사용자 동의 피드백, train/validation/test 분리를 먼저 준비한다.
- 새 대체 종류 관계는 별도 승인된 표와 회귀 사례 없이는 추가하지 않는다.
- 평가지표: AC9 일치, 후보 top-k 적중, 허구 보유 ID 0건, 버킷 이탈 0건, 사용자 선택 일치율.

## 옷장 활용 중심 추천 탭

- 홈 피드: 취향 기반 탐색을 유지한다.
- 추천 탭: 현재 옷장으로 재현 가능한 사진을 우선한다.
- 특정 옷장 아이템 ID를 선택하면 해당 아이템이 실제 후보로 포함되는 사진을 검색한다.
- 의존성: MATCH A안 안정화 → 후보 이유 계약 → 인증/사용자 격리 → 추천 API/페이지네이션.
- 추천 점수와 후보 수는 별도 실험값으로 관리하며 사용 확률로 표현하지 않는다.

## 홈 피드 검색·필터

- 1차 검색 대상은 서버의 canonical `style`, `kind`, `color`다.
- 취향 순서와 검색 결과 정렬을 섞지 않고, 검색/필터가 켜지면 해당 조건 안에서 결정적 순서를 사용한다.
- 빈 결과, 필터 초기화, 동의어 표를 프론트와 합의한다.

## 사진 기반 옷장 등록 서버 연동

- 2026-11-24 확인: 사진 기반 단일 옷장 등록 UI는 PR #27로 main에 병합됐고 PR #31의 Expo production 배포에도 포함됐다. 카메라/앨범→영역 자르기→칩 수정→로컬 등록은 재사용하며 중복 구현하지 않는다. 서버 Storage 동기화, 원본 보존·삭제, AI 태깅·누끼 고도화와 일괄 등록은 별도 정책 이후 진행한다.
- 프론트가 정할 업로드·확인·수정 흐름과 원본 보존 정책을 받은 뒤 API를 설계한다.
- 사용자 확정 전 옷장에 자동 저장하지 않는다.
- 기존 칩 등록은 유지한다.
- LLMOps `feature=wardrobe_photo_tagging`을 재사용하며 사진 원문·전체 프롬프트를 운영 지표에 저장하지 않는다.
- 이미지 구김 제거/형태 보정은 원본 보존·표시 고지·왜곡 평가 정책 확정 전 구현하지 않는다.

## 사진별 챗봇 대화 저장

- 선행 조건: Supabase Auth, 사용자 격리 테스트, 보존/삭제 정책.
- 대화 키는 인증 사용자 + style image + conversation ID로 격리한다.
- 목록/페이지네이션/단건 삭제/사진 삭제 및 계정 삭제 시 연쇄 처리 계약이 필요하다.
- 원문 대화는 LLM 운영 지표와 분리한다. 운영 지표에는 토큰·지연·상태만 저장한다.
- 현재 `POST /chat.history`는 요청 문맥이며 영구 저장을 의미하지 않는다.

## 사용자 비교 피드백

- 명시적 동의 기반 수집 방향은 확정됐다.
- 구체적 동의 문구, 버전, 철회, 보존 기간, 삭제 방식이 미확정이므로 endpoint/migration 운영 적용은 보류한다.
- 일반 행동 이벤트를 학습 라벨로 자동 전환하지 않는다.

## 콘텐츠

- 출시 콘텐츠는 이용 허락을 받은 사진 또는 직접 제작한 콘텐츠만 사용한다.

## Private Beta 1단계 경계 (2026-11-24)

- FEED-01 홈 검색·필터는 PR #34에서 최신 main 기준으로 정리했으며 실기기 QA 전까지 Draft로 유지한다.
- 추천 노출·클릭·조합 도달·선택 계측과 결정적 추천 core는 PR #35에서 정리했다. 취향 기반 fallback 신규 구현은 후속 작업이다.
- MATCH-03 한 줄 근거 UI는 PR #31과 Expo production에 반영됐다. 유사도 점수는 계속 숨긴다.
- PR #30의 인증·챗 기록은 2단계 대상이다. 1단계에서는 검토와 테스트 계획만 수행하고 병합하지 않는다.
- 정식 스토어 등록 요구사항은 삭제하지 않고 출시 재개 백로그로 유지한다. 현재 목표는 콘텐츠 권리가 확보된 제한 Private Beta다.
- `permission` metadata와 공개 전 검수 흐름을 유지한다.
- 출처 표기만으로 이용 허락을 대신하지 않는다.
